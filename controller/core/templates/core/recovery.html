Public recovery information

Vivolution Control Plane Recovery

This page is intentionally available without an operator session so it remains useful during an authentication or database incident. It does not expose logs, topology, configuration data or credential-reset controls.

Check the service boundary

  1. Confirm this browser address is the expected controller FQDN and uses trusted HTTPS.
  2. Open /health/live. HTTP 200 confirms the web process is responding.
  3. Return to the operator sign-in page.

If sign-in is unavailable

Sign in to the Ubuntu VM console or approved SSH endpoint. Inspect installer status with sudo ./installer/install.sh status, resume an interrupted installation with sudo ./installer/install.sh resume, or reconcile a completed installation with sudo ./installer/install.sh reconcile. Create a redacted diagnostic archive with sudo ./installer/install.sh support-bundle when support asks for one, and inspect it before sharing. The initial credential remains in the root-only /var/lib/vivolution-installer/credentials.txt file.

The installer owns the operator credential. Password reset or rotation is not available in this release, and the web password-change endpoints are blocked. Application backup and restore, release upgrades, CP2/CP3 HA and external load-balancer workflows are also unavailable / planned. Do not edit the database, container environment, password hashes or installer state manually.

When contacting support, provide the controller FQDN, UTC time, this installed release identifier—{{ vivolution_release_id }}—and a sanitized error description. Never send passwords, cookies, database URLs, private keys or complete environment files.
